# Every IAM identity is uniquely attributable, root account is dormant

`ISO27001-A.5.16-identity-management` · framework **iso27001** · severity **critical** · Organisational Controls

## What this control checks

ISO/IEC 27001:2022 A.5.16 requires the full life-cycle of identities
to be managed. Concord verifies (a) AWS root has no access keys and
has been idle for ≥90 days, (b) no IAM user shares credentials,
(c) service accounts have no console login.

## Why it matters

Shared credentials and root-account usage break A.5.16 the same way
they break HIPAA §164.312(a)(2)(i): events cannot be attributed to a
real identity, so the rest of A.5.18 (access reviews) and A.8.15
(logging) lose evidentiary value.

## Evidence

Collected from the `aws` source (`iam_account_summary` evidence type).

## What a failure looks like

This control reports a finding when any of the following hold:

- no IAM evidence collected
- root account has access keys — identities must be uniquely attributable
- root account used <value> days ago — investigate
- IAM principal <value> shares credentials with <value> users
- service account <value> has console login enabled

## Remediation

Bring each affected resource or attestation listed under *What a failure looks like* into compliance, then re-collect evidence. Estimated effort: **4h**. Automated fix available: **false**.

## How to re-verify

```
concord check --controls <pack>/controls --framework iso27001 --control-id ISO27001-A.5.16-identity-management
```

A passing run reports this control green; in CI, `concord gate` exits non-zero while it fails.

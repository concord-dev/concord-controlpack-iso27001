# Production data stores have automated backups with tamper-resistant retention

`ISO27001-A.5.30-business-continuity` · framework **iso27001** · severity **critical** · Organisational Controls

## What this control checks

ISO/IEC 27001:2022 A.5.30 requires ICT readiness for business
continuity. Concord verifies every RDS instance and DynamoDB table
tagged production=true has automated backups with retention ≥ 35
days, and that AWS Backup vault locking is configured.

## Why it matters

Vault locking is the operational difference between a "backup
policy" and a "backup the auditor accepts" — without it, a
compromised credential can delete backups.

## Evidence

Collected from the `aws` source (`backup_status` evidence type).

## What a failure looks like

This control reports a finding when any of the following hold:

- no backup evidence collected
- production RDS <value> backup retention <value> days < <value>
- production DynamoDB table <value> has point-in-time recovery disabled
- backup vault <value> holds production data but is not vault-locked

## Remediation

Bring each affected resource or attestation listed under *What a failure looks like* into compliance, then re-collect evidence. Estimated effort: **4h**. Automated fix available: **false**.

## How to re-verify

```
concord check --controls <pack>/controls --framework iso27001 --control-id ISO27001-A.5.30-business-continuity
```

A passing run reports this control green; in CI, `concord gate` exits non-zero while it fails.

# Tier-1 suppliers carry current security certifications, tracked in the Concord vendor register

`ISO27001-A.5.19-supplier-relationships` · framework **iso27001** · severity **high** · Organisational Controls

## What this control checks

ISO/IEC 27001:2022 A.5.19 requires processes to manage information
security risks associated with supplier relationships. Concord
reads the vendor-management attestation export (auto-emitted by
`concord vendor` workflows) and verifies every tier-1 supplier
has a current SOC 2 or ISO 27001 certification on file.

## Why it matters

Tier-1 supplier risk is the most common audit finding under A.5.19.
The Concord vendor register provides the structured evidence; the
attestation export gives the auditor a frozen snapshot.

## Evidence

Collected from the `attestation` source (`policy_attestation` evidence type).

## What a failure looks like

This control reports a finding when any of the following hold:

- no vendor-register attestation collected
- attestation kind is <value>, expected "vendor_register"
- vendor-register attestation cosign signature did not verify
- tier-1 vendor <value> has no acceptable security certification on file
- tier-1 vendor <value> has an expired <value> certification (expired <value>)

## Remediation

Bring each affected resource or attestation listed under *What a failure looks like* into compliance, then re-collect evidence. Estimated effort: **1d**. Automated fix available: **false**.

## How to re-verify

```
concord check --controls <pack>/controls --framework iso27001 --control-id ISO27001-A.5.19-supplier-relationships
```

A passing run reports this control green; in CI, `concord gate` exits non-zero while it fails.

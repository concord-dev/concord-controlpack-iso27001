# S3 buckets enforce TLS on every request via bucket policy

`ISO27001-A.8.24-cryptography` · framework **iso27001** · severity **critical** · Technological Controls

## What this control checks

ISO/IEC 27001:2022 A.8.24 requires rules for the effective use of
cryptography. Concord verifies every S3 bucket carries a bucket
policy that denies requests where aws:SecureTransport is false.

## Why it matters

A.8.24 audits expect TLS enforcement to be configured at the
resource policy level, not just relied on from clients.

## Evidence

Collected from the `aws` source (`s3_bucket_policy` evidence type).

## What a failure looks like

This control reports a finding when any of the following hold:

- no S3 bucket-policy evidence collected
- bucket <value> does not enforce TLS via bucket policy

## Remediation

Bring each affected resource or attestation listed under *What a failure looks like* into compliance, then re-collect evidence. Estimated effort: **30m**. Automated fix available: **true**.

## How to re-verify

```
concord check --controls <pack>/controls --framework iso27001 --control-id ISO27001-A.8.24-cryptography
```

A passing run reports this control green; in CI, `concord gate` exits non-zero while it fails.

# IAM administrators are scarce, named, and use roles not standing access keys

`ISO27001-A.8.2-privileged-access` · framework **iso27001** · severity **critical** · Technological Controls

## What this control checks

ISO/IEC 27001:2022 A.8.2 requires privileged access rights to be
restricted and managed. Concord verifies the count of IAM
principals with AdministratorAccess (or wildcard *:* equivalent)
is bounded, that no admin holds long-lived access keys, and that
every admin is assumable only via SSO + MFA.

## Why it matters

Standing IAM admin keys are the single highest-blast-radius
finding under A.8.2. Auditors want admin count + last-rotation
+ MFA-enrolled status.

## Evidence

Collected from the `aws` source (`iam_privileged_principals` evidence type).

## What a failure looks like

This control reports a finding when any of the following hold:

- no IAM privileged-principals evidence collected
- <value> IAM principals carry AdministratorAccess — A.8.2 says privileged access must be restricted (target ≤ <value>)
- administrator <value> holds a long-lived access key — admin access must be assumable, not static
- administrator <value> is not MFA-enrolled

## Remediation

Bring each affected resource or attestation listed under *What a failure looks like* into compliance, then re-collect evidence. Estimated effort: **1d**. Automated fix available: **false**.

## How to re-verify

```
concord check --controls <pack>/controls --framework iso27001 --control-id ISO27001-A.8.2-privileged-access
```

A passing run reports this control green; in CI, `concord gate` exits non-zero while it fails.

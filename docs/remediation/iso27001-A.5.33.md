# Audit logs (CloudTrail) carry cryptographic log-file validation

`ISO27001-A.5.33-records-protection` · framework **iso27001** · severity **high** · Organisational Controls

## What this control checks

ISO/IEC 27001:2022 A.5.33 requires records to be protected from
loss, destruction, and falsification. For AWS audit logs, the
operational form is CloudTrail log-file validation (every log
digest is signed by AWS).

## Why it matters

Without log-file validation, log tampering by an attacker (or by
accident) is undetectable. A.5.33 specifically calls out
"falsification" as an in-scope threat.

## Evidence

Collected from the `aws` source (`cloudtrail_trails` evidence type).

## What a failure looks like

This control reports a finding when any of the following hold:

- no CloudTrail evidence collected
- no CloudTrail trails configured
- trail <value> has log-file validation disabled

## Remediation

Bring each affected resource or attestation listed under *What a failure looks like* into compliance, then re-collect evidence. Estimated effort: **30m**. Automated fix available: **true**.

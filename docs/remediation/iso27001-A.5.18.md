# User access rights are reviewed on a documented cadence

`ISO27001-A.5.18-access-rights` · framework **iso27001** · severity **high** · Organisational Controls

## What this control checks

ISO/IEC 27001:2022 A.5.18 requires user access rights to be
reviewed at regular intervals. Concord reads a signed
access-review attestation that records the last cycle's
completion date, the reviewers, and the count of decisions
(keep/revoke/escalate).

## Why it matters

Stale access rights are the highest-confidence ISO finding —
quarterly review cadence with documented decisions per
subject is the bar.

## Evidence

Collected from the `attestation` source (`policy_attestation` evidence type).

## What a failure looks like

This control reports a finding when any of the following hold:

- no access-review attestation collected
- attestation kind is <value>, expected "access_review"
- access-review attestation missing field: <value>
- access-review attestation cosign signature did not verify
- last access-review cycle completed <value> days ago — A.5.18 requires quarterly cadence
- <value> subjects in scope but only <value> decisions recorded — review is incomplete

## Remediation

Bring each affected resource or attestation listed under *What a failure looks like* into compliance, then re-collect evidence. Estimated effort: **1w**. Automated fix available: **false**.

## How to re-verify

```
concord check --controls <pack>/controls --framework iso27001 --control-id ISO27001-A.5.18-access-rights
```

A passing run reports this control green; in CI, `concord gate` exits non-zero while it fails.

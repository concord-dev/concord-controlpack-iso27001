# Anti-malware telemetry (GuardDuty + Inspector) covers every active region

`ISO27001-A.8.7-malware-protection` · framework **iso27001** · severity **high** · Technological Controls

## What this control checks

ISO/IEC 27001:2022 A.8.7 requires controls to protect against malware,
combined with user-awareness. Concord verifies GuardDuty is enabled
in every active region and Inspector is enabled at the account level
for EC2 and ECR scanning.

## Why it matters

A.8.7 is the technical counterpart to A.6.3 awareness training.
GuardDuty covers network/DNS threat surfaces; Inspector covers
EC2 OS and container-image vulnerabilities.

## Evidence

Collected from the `aws` source (`anti_malware_status` evidence type).

## What a failure looks like

This control reports a finding when any of the following hold:

- no anti-malware evidence collected
- GuardDuty disabled in active region <value>
- AWS Inspector is not enabled at the account level
- Inspector is enabled but does not include <value> resource scanning

## Remediation

Bring each affected resource or attestation listed under *What a failure looks like* into compliance, then re-collect evidence. Estimated effort: **1h**. Automated fix available: **true**.

## How to re-verify

```
concord check --controls <pack>/controls --framework iso27001 --control-id ISO27001-A.8.7-malware-protection
```

A passing run reports this control green; in CI, `concord gate` exits non-zero while it fails.

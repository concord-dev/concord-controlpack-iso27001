# Documented access-control policy exists, is current, and is signed by management

`ISO27001-A.5.15-access-control-policy` · framework **iso27001** · severity **high** · Organisational Controls

## What this control checks

ISO/IEC 27001:2022 A.5.15 requires an access-control policy that
defines rules for granting, revoking, and reviewing access. Concord
reads a cosigned attestation YAML from the policy repository.

## Why it matters

A.5.15 is the meta-control that anchors A.5.16, A.5.17, A.5.18, and
A.8.2. Without a current signed policy, auditors will not credit
the operational controls below it.

## Evidence

Collected from the `attestation` source (`policy_attestation` evidence type).

## What a failure looks like

This control reports a finding when any of the following hold:

- no access-control-policy attestation collected
- attestation kind is <value>, expected "access_control_policy"
- attestation missing required field: <value>
- policy review is overdue (next_review_due=<value>)
- attestation cosign signature did not verify

## Remediation

Bring each affected resource or attestation listed under *What a failure looks like* into compliance, then re-collect evidence. Estimated effort: **1d**. Automated fix available: **false**.

## How to re-verify

```
concord check --controls <pack>/controls --framework iso27001 --control-id ISO27001-A.5.15-access-control-policy
```

A passing run reports this control green; in CI, `concord gate` exits non-zero while it fails.

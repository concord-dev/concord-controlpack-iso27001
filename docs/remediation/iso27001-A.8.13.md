# Backup restore is exercised on a documented cadence with a successful last run

`ISO27001-A.8.13-information-backup` · framework **iso27001** · severity **high** · Technological Controls

## What this control checks

ISO/IEC 27001:2022 A.8.13 requires backup *and* restoration testing.
Concord verifies the latest scheduled restore-test has run within
the configured window and was successful.

## Why it matters

A.5.30 covers the existence of backups; A.8.13 covers whether they
actually work. Untested backups are a recurring audit finding.

## Evidence

Collected from the `aws` source (`backup_restore_tests` evidence type).

## What a failure looks like

This control reports a finding when any of the following hold:

- no restore-test evidence collected
- no restore tests have ever been executed
- no restore tests have ever succeeded
- most recent restore test was <value> days ago (max <value>)
- most recent restore test (<value>) failed: <value>

## Remediation

Bring each affected resource or attestation listed under *What a failure looks like* into compliance, then re-collect evidence. Estimated effort: **4h**. Automated fix available: **false**.

## How to re-verify

```
concord check --controls <pack>/controls --framework iso27001 --control-id ISO27001-A.8.13-information-backup
```

A passing run reports this control green; in CI, `concord gate` exits non-zero while it fails.
